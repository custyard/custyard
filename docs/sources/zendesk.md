The flow: you configure a Zendesk webhook to POST to custyard's `/api/webhook/route/:callback_token` endpoint. When a Zendesk ticket is created or updated, Zendesk fires that webhook. The `WebhookController.routed/2` action looks up the inbound route by `callback_token`, finds `source: :zendesk` on the route record, and dispatches to `Custyard.Webhooks.Adapters.Zendesk`. That adapter verifies the HMAC-SHA256 signature, normalizes the Zendesk ticket payload (requester email, subject, body, ticket ID) into custyard's internal message format, and feeds it into the processing pipeline — creating or updating a conversation.

So "source" on an inbound route tells the webhook controller which adapter to use for signature verification and payload normalization. The adapter infrastructure is fully wired — the Copilot reviewer's concern was specifically that `create_route/1` provisions a remote Lettermint mailbox regardless of source, and `callback_url/1` hardcodes a Lettermint-style URL. For Zendesk you wouldn't need a Lettermint mailbox; you'd just need the callback URL and a shared signing secret.

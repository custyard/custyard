Lettermint is the default and currently the only fully integrated source. When you create an inbound route via `InboundRoutes.create_route/1`, the function provisions a remote Lettermint route (via `Client.client().create_route/1`), stores the returned `lettermint_route_id` on the local `InboundRoute` record, and generates a callback URL that includes `source=lettermint` in the query string.

The flow: Lettermint receives email at a per-organization mailbox address, then POSTs the parsed email payload to custyard's `/api/webhook/route/:callback_token` endpoint. The `WebhookController.routed/2` action looks up the inbound route by `callback_token`, finds `source: :lettermint` on the route record, and dispatches to `Custyard.Webhooks.Adapters.Lettermint`. That adapter verifies the HMAC-SHA256 signature (with optional `sha256=` prefix stripping), normalizes the email fields (from, to, subject, body, message-id, in-reply-to, references headers) into custyard's internal message format using `Email.Normalizer`, and feeds it into the processing pipeline — creating or threading into conversations.

Lettermint is the only source where `create_route/1` and `callback_url/1` are fully source-aware. The other adapters (Zendesk, Intercom, Slack) have complete webhook verification and payload normalization, but route creation still provisions a Lettermint mailbox regardless of the selected source, and `callback_url/1` hardcodes `source=lettermint` in the URL. Making `create_route/1` and `callback_url/1` source-aware is the remaining work to fully support non-Lettermint sources at the route management level.
